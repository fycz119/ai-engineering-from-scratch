核心洞察

距离不是数据的属性，而是你做出的 假设。换一个范数，就是换一种「什么算相似」的世界观。

01

距离，就是你对「相似」的定义

同一份数据、同一个查询点，只换一种度量，最近邻就换了一个人。你的 KNN、推荐系统、向量数据库、聚类和损失函数，全都建立在这个选择之上。

02

范数：先量「大小」，再量「距离」

范数把向量映射成一个非负标量。理解它的关键不是公式，而是三条公理——以及一个恒等式：任意距离都可以写成「差的范数」。

给你两个向量，你真正想知道的是：它们有多接近？由于 d(a, b) = ‖a − b‖，只要有了范数，距离就自动有了。下面拖动两个箭头，验证范数必须满足的三件事。

03

L1 范数：城市网格上的曼哈顿距离

L1 把每个分量的绝对值加起来。它像在曼哈顿的街道上打车：只能沿轴走，不能斜穿。所以它的等距线是一个菱形，而不是圆。

04

L2 范数：几何课里的直线距离

L2 是分量平方和的平方根，也就是把毕达哥拉斯定理推广到 n 维。它允许斜穿，所以等距线是正圆。这是最符合直觉、也最常用的距离。

05

Lp 家族：一条公式，无穷种「圆」

L1 和 L2 不是两个孤立的公式，而是同一个家族的 p = 1 与 p = 2。p 决定单位球的形状：p 越小越尖，p 越大越方。

边界情况 p < 1 时它不是范数：形状向内凹陷，三角不等式失效。所以 Lp 只在 p ≥ 1 时才能作为距离。
06

L∞ 范数：只看最坏的那一维

当 p 趋于无穷，Lp 收敛到「最大绝对分量」。两点之间的距离由它们差异最大的那一维决定，其他维度全部被忽略。国际象棋里的王，走一步的代价就是 L∞ 距离。

07

余弦相似度：只问方向，不问长度

余弦相似度测量两个向量的夹角，把大小完全丢掉。在文本与嵌入的世界里，长度往往是噪声，方向才是语义——所以余弦几乎统治了 NLP。

为什么 NLP 选择余弦

一篇讲猫的文章，长度翻倍后仍然「相似」。词分布相同、长度不同的两篇文档指向同一方向，余弦相似度为 1.0。余弦把方向与长度解耦，而长度通常只反映文档长短，不代表语义强度。

TF-IDF / 词嵌入 / 句嵌入 推荐系统偏好向量 向量数据库检索
几何直觉 余弦相似度 = 把两个向量都单位化之后再取点积。画在单位圆上，它只取决于两个箭头指向哪里，与箭头有多长无关。
08

点积 vs 余弦：长度算不算信息？

点积 = 余弦 × 两个模长。向量已单位化时，两者完全相同；否则点积会额外奖励「更长」的向量——这既可能是噪声，也可能是你想要的流行度信号。

09

马氏距离：先理解数据的形状，再量距离

欧氏距离把所有维度当作互不相关、尺度相同。但身高与体重相关、特征尺度不同时，L2 会误导。马氏距离用协方差矩阵先白化数据，再在变换后的空间里量 L2。

10

Jaccard：集合之间的重叠，不是向量之间的距离

当数据天然是「一堆标签」而不是「一串数字」时，欧氏距离帮不上忙。Jaccard 只问一件事：交集占并集的比例是多少？

KL 散度：很常用，但它不是「距离」

KL 散度衡量「用 Q 来编码 P 会多付多少比特」。它非常有用，但不对称、也不满足三角不等式——严格来说，它是一个散度（divergence），不是距离。

13

Wasserstein 距离：把一堆土搬到另一个坑里

如果 P 是一堆土、Q 是一个坑，Wasserstein 距离就是最少要搬多少土、搬多远。它是真正的度量，而且即使两个分布完全不重叠，也依然能给出有意义的梯度。

关键术语：人们怎么说，它到底是什么

计算 (1, 2, 3) 与 (4, 0, 6) 的 L1、L2、L∞，并证明 L∞ ≤ L2 ≤ L1

差向量 d = (3, −2, 3)。

参考解 L1 = 3 + 2 + 3 = 8；L2 = √(9 + 4 + 9) = √22 ≈ 4.690；L∞ = max(3, 2, 3) = 3。

为什么 L∞ ≤ L2：设 m = max|dᵢ|，则 L2² = Σdᵢ² ≥ m²，开方即得。
为什么 L2 ≤ L1：L1² = Σdᵢ² + 2Σ|dᵢ||dⱼ| ≥ Σdᵢ² = L2²。
一般地，对 p₁ < p₂ 有 ‖x‖p₂ ≤ ‖x‖p₁，所以 L∞ ≤ L2 ≤ L1 是必然的。
构造两对向量：余弦高但 L2 大；余弦低但 L2 小

提示：余弦只看方向，L2 同时看方向和长度。要「方向几乎一样、距离很远」，就沿同一方向拉长；要「方向差很多、距离很近」，就让两个向量都很短。

参考解 高余弦、大 L2：a = (100, 0)，b = (99, 10)。cos ≈ 0.995，L2 = √(1² + 10²) ≈ 10.05。
低余弦、小 L2：a = (0.5, 0)，b = (0.05, 0.2)。cos ≈ 0.243（< 0.3），L2 = √(0.45² + 0.2²) ≈ 0.492（< 0.5）。
几何解释：两个向量都很短，所以端点近；但 b 几乎垂直于 a，所以夹角大。
构造一个数据集，让 L1 / L2 / L∞ / 余弦四个最近邻各不相同

试试「交互实验 01」的数据：查询点 q = (2, 1)，数据点 P0–P7。

参考解 取 P0=(5,2)、P1=(5.4,1.3)、P2=(4.3,3.3)、P3=(8,4.1)、P4=(−0.5,3)、P5=(6.5,−0.5)、P6=(−1.5,0)、P7=(4,4.5)。
L1 最近邻是 P1（3.70），L2 是 P0（3.16），L∞ 是 P2（2.30），余弦是 P3（cos ≈ 0.9998）。
直观原因：L1 偏爱「稀疏」的点，L2 偏爱整体近的点，L∞ 只看最大的那一维，余弦则完全无视距离、偏爱与原点同向的点。
用 CDF 方法手算 Wasserstein：哪个更大？

第一组：P = [0.5, 0.5, 0, 0]，Q = [0, 0, 0.5, 0.5]。第二组：P = [0.25, 0.25, 0.25, 0.25]，Q = [0, 0, 0.5, 0.5]。

参考解 第一组：CDF_P = [0.5, 1, 1, 1]，CDF_Q = [0, 0, 0.5, 1]；差的绝对值在边界 0、1、2 上分别是 0.5、1、0.5，和为 2。
第二组：CDF_P = [0.25, 0.5, 0.75, 1]，CDF_Q = [0, 0, 0.5, 1]；差为 0.25、0.5、0.25，和为 1。
第一组更大：它需要把所有质量整体搬运 2 个格子；第二组一半质量就地不动，另一半只搬 1 格。
实现 MinHash 近似 Jaccard，并观察误差随哈希函数数量的变化

思路：对集合中每个元素算 k 个哈希，取每个哈希的最小值作为签名；两个签名的逐位相等比例，就是 Jaccard 的无偏估计。

参考解（Python 骨架） 
import random
def minhash_signature(s, k, seed=0):
    rnd = random.Random(seed)
    a = [rnd.randrange(1, 2**61) for _ in range(k)]
    b = [rnd.randrange(1, 2**61) for _ in range(k)]
    return [min((a[i] * x + b[i]) % (2**61 - 1)) for x in s]
            for i in range(k)]

def estimate_jaccard(s1, s2, k):
    sig1, sig2 = minhash_signature(s1, k), minhash_signature(s2, k)
    return sum(x == y for x, y in zip(sig1, sig2)) / k

# 生成 100 个随机集合，比较真实 Jaccard 与 k=50/100/200 的估计

误差随 k 增大按 1/√k 下降（标准差 ≈ √(J(1−J)/k)）。所以 k=200 通常已足够稳定，这也是 MinHash 能撑起大规模去重的原因。

01 · 几何优先
范数 → 单位球 → 距离
p 控制单位球的形状。L1 的角带来稀疏，L2 的光滑带来稳定，L∞ 的平面带来最坏情况思维。看到公式，先在脑子里画出它的单位球。

相似 ≠ 近
